## 1. 项目概览

TestHub 是一个 **AI 驱动的全栈测试管理平台**，集成需求分析、用例管理、API 测试、UI 自动化、APP 自动化等能力。

### 1.1 核心业务流程

```
需求文档上传 → AI 需求澄清 → AI 生成用例 → 4表格瀑布流 → 用例评审 → 导入/导出 → 执行管理
```

### 1.2 技术亮点

| 特性 | 实现 |
|------|------|
| AI 流式生成 | 3阶段回调 writing→reviewing→revising，实时落盘 |
| 4表格瀑布流 | 需求拆分表 / AI编写表 / AI评审表 / 最终版用例表 |
| 增量改稿 | `merge_revised_cases` 按 case_id 合并，[DELETE] 标记删除 |
| 批量导入 | Excel/CSV 自动映射中文表头，优先级标准化 |
| 多模型支持 | 13+ AI 提供商，按角色配置 |

#### 5.1.2 AI 生成流水线

```
用户创建任务 (status=pending_clarification)
    ↓
AI 澄清对话 (Clarifier Prompt V3: 宁可多问)
    ↓ 用户确认或跳过
开始生成 (status=generating)
    ↓
阶段1: Writing (status=writing, progress=10→60)
    ├── AI 输出 [MODULES] 模块拆分表
    ├── AI 输出 [TESTCASES] 用例表
    ├── stream_callback 实时落盘（每300字符）
    └── 完成后拆分: requirement_breakdown + stream_buffer
    ↓
阶段2: Reviewing (status=reviewing, progress=70)
    ├── AI 评审已生成用例
    └── review_stream_callback 实时落盘
    ↓
阶段3: Revising (status=revising, progress=85)
    ├── AI 根据评审意见改稿
    ├── merge_revised_cases 增量合并（[DELETE]标记删除）
    ├── 自动剥离 [MODULES] 部分
    └── final_callback 实时落盘
    ↓
完成 (status=completed, progress=100)
    └── final_test_cases 保存最终用例
```

#### 5.1.3 流式回调关键代码

```python
# views.py — stream_callback
async def stream_callback(chunk):
    nonlocal last_saved_position
    task.stream_buffer += chunk
    task.stream_position = len(task.stream_buffer)

    # 每累积 300 字符保存一次
    if (task.stream_position - last_saved_position >= SAVE_INTERVAL):
        await async_save_stream_buffer(task.stream_buffer)
        last_saved_position = task.stream_position
```

**关键教训：**
- `sync_to_async` 在 daemon 线程中执行 ORM save，需要确保事务可见性
- `task.save()` 不带 `update_fields` 会覆盖已保存的 stream_buffer
- 拆分逻辑要在 if/else 内部赋值，不能在外部"兜底"赋值

## 9. AI 模块深度解析

### 9.1 Prompt 版本历史

| 版本 | 变更 | 状态 |
|------|------|------|
| V1-V6 | 基础用例生成 | 废弃 |
| V7 | 单一Markdown表格 + 模块列 | 废弃 |
| V10 | 4表格瀑布流方案设计 | 废弃 |
| V11 | 模块覆盖统计表 + 强制逐模块覆盖 | 废弃 |
| **V12** | [MODULES]+[TESTCASES] 双表标记 | **当前使用** |

### 9.2 Writer Prompt V12 核心要求

```
1. 先输出 [MODULES] 模块拆分表
   | 模块 | 功能点 | 优先级 | 说明 |

2. 再输出 [TESTCASES] 用例表
   | 所属模块 | 用例ID | 测试目标 | 前置条件 | 操作步骤 | 预期结果 | 优先级 |

3. 每个模块至少 5 条用例（强制覆盖）

4. 保留抽奖专属规则、通用场景覆盖
```

### 9.3 Clarifier Prompt V3

```
策略：宁可多问
- 第一轮必须提 3-8 个问题
- 不能零问题直接 [CLARIFICATION_DONE]
- 问题要覆盖：功能边界、异常场景、权限、数据、性能
```

## 11. 常见问题排查

| 问题 | 根因 | 解决方案 |
|------|------|---------|
| MySQL 中文乱码 | PowerShell GBK 编码 | 用 `--default-character-set=utf8mb4` |
| Django 启动卡死 | PowerShell 输出重定向阻塞 | 用 `Start-Process -WindowStyle Normal` |
| Vite 被 SIGKILL | exec 超时 | 用 `background: true` |
| 流式输出不显示 | stream_buffer 未落盘 | 重启 Django 确保新代码生效 |
| 浏览器缓存旧数据 | axios GET 无防缓存头 | api.js 添加 no-cache + _t 时间戳 |
| 澄清面板残留 | 状态竞态条件 | 4重防护（skip/load/fetch轮询/v-if） |
| 吸顶空白区域 | placeholder 堆积 | initStickyHeader 前清理旧 placeholder |
| 批量导入失败 | 未安装 openpyxl | `pip install openpyxl` |
