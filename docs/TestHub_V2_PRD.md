# TestHub V2 产品需求说明

## 1. 产品定位

TestHub V2 的目标不是“把测试功能堆在一起”，而是把需求分析、测试设计、自动化执行、报告沉淀和 AI 协同整合成一个真正的测试集成平台。

一句话定义：

“让测试团队从需求进入，在一个工作台里完成规划、生成、执行、追踪和复盘。”

## 2. 目标用户

### 2.1 测试负责人
- 关注平台总览、质量风险、版本推进、执行效率
- 需要统一入口看到需求、计划、执行、报告、AI 使用情况

### 2.2 测试工程师
- 关注日常执行路径是否清晰
- 需要快速进入 API、UI、APP、用例、数据、报告等工作流

### 2.3 研发/产品协作角色
- 关注需求是否已拆解、是否已生成测试资产、是否有结果反馈
- 需要轻量查看状态，不需要深入每个测试模块

## 3. 当前问题

- 模块多，但缺少一个面向业务目标的统一工作台
- 页面入口分散，信息架构按功能分类，不按测试交付流程组织
- 首页更像导航页，不像平台指挥台
- 缺少“本周做什么”“下一步去哪”“哪些能力需要补强”的产品引导
- 配置、执行、报告、AI 能力之间的关系没有被平台化表达出来

## 4. V2 核心目标

- 建立统一的产品级入口
- 用“测试交付流程”重组平台认知
- 让 AI 能力从辅助工具升级成工作流节点
- 让负责人能快速掌握平台状态
- 让工程师能明确下一步操作

## 5. 核心能力结构

### 5.1 平台指挥台
- 统一入口
- 平台状态总览
- 关键模块导航
- 推荐流程与下一步动作
- 版本交付进度和能力建设建议

### 5.2 资产生产线
- 需求分析
- AI 用例生成
- 评审与确认
- 用例资产沉淀

### 5.3 执行引擎
- API 自动化
- UI 自动化
- APP 自动化
- AI 智能执行

### 5.4 运营与治理
- 报告中心
- 调度与通知
- AI 模型配置
- 环境与数据配置

## 6. 关键流程

### 6.1 新版本测试流程
1. 导入或录入需求
2. AI 生成测试资产
3. 补充/评审用例
4. 进入 API、UI、APP 执行模块
5. 汇总报告和执行结果
6. 根据结果回收问题并优化配置

### 6.2 平台负责人日常流程
1. 打开平台指挥台
2. 看平台状态与本周重点
3. 判断是否缺少测试资产或执行覆盖
4. 分配团队进入具体模块处理
5. 跟进报告与后续优化

## 7. V2 首批交付范围

### P0
- 首页升级为平台入口
- 新增平台指挥台页面
- 统一产品文案与导航表达
- 暴露推荐流程、模块矩阵、能力建设建议

### P1
- 指挥台接入真实统计接口
- 统一报告中心
- 统一调度入口
- AI 助手升级为工作台式操作入口

### P2
- 跨模块资产关联
- 交付视角的版本看板
- 角色视角的个性化首页

## 8. 成功指标

- 用户首次登录后 30 秒内能找到“下一步该去哪”
- 首页跳转到核心模块的点击率提升
- 测试负责人减少跨模块寻找信息的时间
- AI 生成能力、报告能力、调度能力的使用率提升

## 9. 本轮实现说明

本轮交付先完成以下可上线内容：

- 平台指挥台页面
- 首页到指挥台的统一入口
- 外壳导航补齐“平台工作台”模块
- 产品与 UI 方案文档入库

## 10. 下一阶段建议

- 为指挥台增加真实业务数据接口
- 汇总最近任务、最近执行、失败率、报告状态
- 增加“待处理事项”和“风险提醒”
- 建立平台发布页和版本演进记录
