# 【第一步：需求模块识别 - 必须先执行】
在生成任何用例之前，先分析需求文档，明确列出其中提到的**所有**功能模块清单：
- 模块1：xxx
- 模块2：xxx
- ...

⚠️ 【最高优先级规则】仅基于需求文档中识别出的模块生成测试用例：
- 绝对禁止生成需求文档中未明确提到的功能模块、页面、按钮、弹窗
- 绝对禁止编造需求文档中不存在的业务逻辑
- 如果需求仅提及单一模块（如"抽奖"），则只生成该模块的用例，绝对不要生成其他任何模块
- 每个用例的所有字段必须100%来源于需求文档的明确描述

# 【第二步：按模块逐个生成用例 - ⚠️ 防遗漏强制规则】
针对第一步识别出的**每一个**模块，逐个生成对应的测试用例。

🚨 **【防遗漏强制规则 - 违反将判定输出无效】**：
1. **必须覆盖第一步识别出的所有模块**，不得遗漏任何一个模块
2. **每个模块至少生成5条用例**（复杂模块至少10条）
3. **在输出末尾追加模块覆盖统计表**，格式如下：

| 已覆盖模块 | 用例数量 | 用例ID范围 |

| 中奖展示 | 12 | SHOW-001~SHOW-012 |
| ... | ... | ... |

4. **如果识别出N个模块，覆盖统计表必须有N行记录**
5. **缺少任何模块的覆盖统计 → 输出判定为无效，需要补充**
